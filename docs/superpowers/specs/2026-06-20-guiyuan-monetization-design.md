# 归源 · 变现设计草案（产品优先 · 低反感版）

## 1. 核心决策

**先产品后计费。** 不在现阶段开发计费/支付系统，优先把产品价值链路做扎实，
等用户自然增长到一定规模后再逐步引入额度边界与付费通道。

### 开发顺序（三阶段）

| 阶段 | 目标 | 交付内容 | 不做 |
|---|---|---|---|
| **Phase A：产品闭环** | 核心体验稳定可用 | 编辑、导出、分享、协作、小程序基础体验 | 不锁任何功能 |
| **Phase B：增长边界** | 明确免费额度与自然升级点 | 免费上限定义、温和提示、方案对比页 | 不接支付 |
| **Phase C：付费通道** | 验证付费意愿并落地 | 订阅、支付、额度解锁、账单 | — |

## 2. 定价模型（规划用，Phase C 落地）

采用 **个人订阅 + 组织订阅** 双层模型：

### 2.1 套餐划分

| 层级 | 典型用户 | 核心价值 | 建议定价关键词 |
|---|---|---|---|
| Free | 个人、试用用户 | 完整记录体验，支持基本查看/整理 | 免费 |
| Personal Pro | 已建立较大族谱的个人用户 | 更大容量、导出发布、分享保护、版本保留 | 个人订阅 |
| Org | 家族委员会/宗亲组织/修谱服务方 | 协作空间、权限管理、审核、多分支管理 | 组织订阅 |

### 2.2 计费指标建议（综合）

- 基础：节点数量 / 族谱数量 / 存储规模
- 进阶：高清导出、PDF/HTML 发布、分享保护、历史版本
- 组织：成员数、协作者数、分支挂载数量、审核流、优先支持

## 3. 低反感原则

- 不锁"核心记录能力"。
- 只在自然增长点提示升级：节点上限、导出发布、多人协作、长期托管。
- 升级提示应体现"阶段变化"，而非"能力惩罚"。
- 免费版仍应足够好用，让用户愿意继续经营族谱。

## 4. 建议文案与触发时机

### 4.1 文案方向

- 标题：`你的族谱正在长大`
- 正文：`当族谱规模、多人协作或正式发布需求增加时，可升级以获得更高容量与发布能力。`
- 组织版提示：`多分支与多人编辑需求变多后，建议启用组织空间，避免权限混乱。`

### 4.2 触发点（Phase B 实施）

| 场景 | 触发点 | 避免的做法 |
|---|---|---|
| 节点上限 | 超过免费额度并尝试新增/导出 | 编辑中途突然中断 |
| 导出发布 | 高清 PDF / HTML / 分享加密 | 浏览基础页面强弹窗 |
| 多人协作 | 协作者数量或分支数量增长 | 基础查看也被迫登录/付费 |
| 组织管理 | 多分支、审核流、权限复杂度上升 | 默认强制进入组织付费流程 |

## 5. 当前阶段（Phase A）任务清单

先不碰计费，专注产品闭环：

1. 核心编辑体验稳定（画布、拖拽、保存、冲突处理）
2. 导出分享链路完整（HTML/SVG/PDF/JSON）
3. 协作权限链路清晰（邀请、角色、脱敏）
4. 小程序基础体验可用（查看、分享、简单编辑）
5. 关键 bug 修复与性能优化

## 6. 风险与缓解

- **开源用户反感**：避免把基础功能藏起来；公开免费边界。
- **定价过早过细**：先 3 个方案，不做复杂阶梯。
- **组织客户需求分散**：先通过人工沟通确认高频需求，再固化产品能力。

## 7. 后续路线

Phase A 完成后 → 进入 Phase B（增长边界设计与实施）→ 验证数据后 → 进入 Phase C（付费通道）。
