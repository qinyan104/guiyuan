# 05 — 让手动分页符可见、可保存、可删除

**What to build:** 让族谱编修者可以在两个逻辑块之间插入手动分页符，在编辑器中看见、选择和删除它，并让保存、重新载入和自动重排始终保留分页意图，而成品 PDF 不显示操作标记。

**Blocked by:** 01 — 建立共享的规范化排版基线

**Status:** resolved

- [x] 用户能够在两个逻辑块之间插入手动分页符，后续内容从新页开始
- [x] 编辑器以明确的非打印标记显示分页符，并支持选择和删除
- [x] 分页符具有稳定的逻辑块间锚点，前文内容变化和自动重排不会删除或漂移其分页意图
- [x] 保存并重新打开书稿后，手动分页符及其分页效果保持不变
- [x] 删除分页符后，相关内容恢复自动流动，不留下无来源空白页或空白正文
- [x] 编辑预览的正式版心和矢量 PDF 都不绘制分页符操作标记
- [x] 不含分页符的既有书稿无需迁移即可继续打开、编辑和导出
- [x] 测试覆盖插入、保存重载、重排保留、删除及 PDF 排除标记

## Answer

手动分页符继续使用现有 `pageBreak` 逻辑块，稳定保存在相邻内容块之间。选中可排版块后可插入分页，标记显示在正式书页之外；选中标记即可删除，删除后正文恢复自动流动。连续分页符会堆叠显示，旧版留下的文末或唯一分页符也仍可见、可选、可删除。

保存 API 原样持久化整份书稿 JSON，因此分页符保存重载后保持位置和分页效果；PDF 忽略分页符块，纯标记书稿不会生成空白 PDF 页。不含分页符的既有书稿无需迁移。

验证：前端 63 个测试文件、300 项测试通过，生产构建通过；双轴代码审查发现的 3 项兼容与可访问性问题均已关闭。依赖审计仍报告 9 项既有漏洞（8 高危、1 严重），未自动修改依赖。
