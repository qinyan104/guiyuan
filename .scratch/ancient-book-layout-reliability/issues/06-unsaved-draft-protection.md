# 06 — 保护书稿未保存修改

**What to build:** 让正文、版式和手动分页符的变化都进入清晰的未保存状态，并在保存成功前保护这些修改。族谱编修者返回、切换路由、刷新或关闭页面时，不会再静默丢失书稿。

**Blocked by:** 05 — 让手动分页符可见、可保存、可删除

**Status:** resolved

- [x] 初次载入、初次生成或最近一次保存成功的书稿被视为已保存基线
- [x] 修改正文、版式设置、插入分页符或删除分页符后立即进入未保存状态
- [x] 工具栏清楚显示当前书稿是否存在未保存修改
- [x] 保存成功后更新已保存基线并清除未保存状态
- [x] 保存失败后保留当前编辑内容和未保存状态，不把失败显示为成功
- [x] 返回画布或切换路由时，未保存书稿会触发离开保护；取消后仍停留并保留内容
- [x] 刷新或关闭浏览器页面时，未保存书稿会触发浏览器离开保护
- [x] 没有未保存修改时不会出现多余拦截
- [x] 测试覆盖三类修改、保存成功与失败、确认离开与取消离开

## Answer

- 用 `title`、`layout`、`blocks` 的内容快照作为唯一保存基线；载入、生成和成功保存后更新基线。
- 正文、版式和分页符变化共用工具栏未保存提示；失败及保存期间的新编辑均保留，重试时不会残留旧成功提示。
- 路由返回/切换与浏览器刷新/关闭仅在书稿未保存时拦截。
- 验证：前端 64 个测试文件、306 项测试全部通过，生产构建通过；规格与规范复核无发现。依赖审计仍报告既有 8 个高危、1 个严重漏洞，未在本工单中自动升级依赖。
