# 04 — 让缺失字形逐字符回退

**What to build:** 当用户选择的首选字体缺少汉字或中文标点时，只让缺失字符使用固定的全字形 CJK 后备字体，并让编辑预览与矢量 PDF 使用完全相同的字体选择结果。

**Blocked by:** 01 — 建立共享的规范化排版基线

**Status:** resolved

- [x] 首选字体支持的字符继续使用首选字体，不发生整页或整段替换
- [x] 缺失的汉字和中文标点仅对相应字符使用固定 CJK 后备字体
- [x] 后备字体资源能够在编辑预览和 PDF 导出环境中稳定使用，并满足随成品使用的授权要求
- [x] 规范化排版结果明确记录实际字体选择，两个渲染器不再依赖各自的隐式回退
- [x] 编辑预览与矢量 PDF 使用相同的字体片段顺序，不出现缺字方框、空白字符或静默丢字
- [x] PDF 继续输出矢量文字，不因字体回退退化为页面截图
- [x] 测试覆盖完全支持、单个汉字缺失、标点缺失及连续混合字体片段

## Answer

规范化分页结果现在逐字符记录实际字体：首选字体支持的字符保持不变，缺失汉字和中文标点依次使用 HanaMinA、Jigmo、Jigmo2、Jigmo3。码点判断显式覆盖 Unicode 17 扩展 J，代理对不会在分栏时被拆开；字体临时失败可重试，未使用的可选后备失败也不会阻断编辑器。

编辑预览直接按规范化字体片段渲染，PDF 以相同顺序嵌入并绘制矢量字形。Jigmo 20250912 字体与 CC0 许可证随项目发布，来源和 Unicode 17 覆盖见 [Jigmo 官方说明](https://kamichikoichi.github.io/jigmo/)。

验证：前端 61 个测试文件、292 项测试通过，生产构建通过，双轴代码审查发现的 3 项边界问题均已关闭。依赖审计仍报告 9 项既有漏洞（8 高危、1 严重），未自动修改依赖。
